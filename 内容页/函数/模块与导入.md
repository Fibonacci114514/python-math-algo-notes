> **说明**:模块是函数之上的第一层复用单位,也是对"名称绑定"的显式管理.本文从"函数写好了,怎么让另一个文件也能用"这个问题出发,讲清 `import` 的三种写法、`__name__` 守卫、`sys.path` 的搜索顺序与同名冲突,并指出库在物理上就是一组放在可搜索路径里的 `.py` 文件——最后把它接到数学的"引理—定理"分层,以及 λ 演算里"计算 = 命名 + 组合"这条线上.

---

#### 1. 为什么需要模块

当一个函数需要在多个文件中使用时,复制粘贴会带来两个问题:

| 问题 | 后果 |
| :--- | :--- |
| 代码重复 | 同一个函数存在多份副本 |
| 维护困难 | 修改一处逻辑,需要同步修改所有副本,容易遗漏 |

模块机制让函数只定义一次,其他文件通过 `import` 引用.修改源文件后,所有导入方自动获得更新.

---

#### 2. 三种导入方式

假设有文件 `质数判定模块.py`:

```python
def ifp(x):
    for i in range(2, x):
        if x % i == 0:
            return False
    return True
```

##### 2.1 导入整个模块

```python
import 质数判定模块

print(质数判定模块.ifp(97))   # True
```

- 优点:命名空间清晰,不会与本地变量冲突.
- 调用时需要加模块名前缀.

##### 2.2 导入指定函数

```python
from 质数判定模块 import ifp

print(ifp(97))   # True
```

- 优点:调用简洁.
- 风险:如果本地已有同名函数或变量,会被覆盖.

##### 2.3 导入所有(不推荐)

```python
from 质数判定模块 import *

print(ifp(97))   # True
```

- 优点:写法最短.
- 风险:污染当前命名空间,来源不清晰,大型项目中容易引发冲突.

> **推荐原则**:优先用 `import mod` 或 `from mod import func`,避免 `import *`.`from math import *` 在学习阶段常见,但在多模块协作中应尽量避免.

#### 3. 被导入模块的执行问题与 `__name__` 守卫

`import` 一个模块时,Python 会**执行该模块的顶层代码**.如果模块末尾有直接运行的语句,导入时也会被执行.

```python
# 质数判定模块.py
def ifp(x):
    ...

for m in range(2, 1000):   # 顶层代码,导入时也会执行
    if ifp(m):
        print(m)
```

任何 `import 质数判定模块` 都会触发这个循环并打印大量数字.

##### 3.1 解决方案:`if __name__ == '__main__'`

```python
def ifp(x):
    ...

if __name__ == '__main__':
    for m in range(2, 1000):
        if ifp(m):
            print(m)
```

| 运行方式 | `__name__` 的值 | 守卫块是否执行 |
| :--- | :--- | :--- |
| `python 质数判定模块.py` | `'__main__'` | 执行 |
| `import 质数判定模块` | `'质数判定模块'` | 跳过 |

**作用**:让同一个文件既能"独立运行测试",又能"被安全导入".

#### 4. 库的本质:它就是一组函数

`import random` 与 `import 质数判定模块` 在机制上**完全相同**:Python 去某个目录找一个名为 `random` 或 `质数判定模块` 的 `.py` 文件,执行它,然后把其中的名字暴露给调用方.

可以亲自验证:

```python
import random
print(random.__file__)
```

输出的是 `random.py` 的完整路径.打开这个文件,会看到 `random()`、`randint()`、`shuffle()` 等函数的真实实现——就是普通的 Python 代码.

##### 4.1 两种库的存在形式

| 形式 | 说明 | 示例 |
| :--- | :--- | :--- |
| 纯 Python 库 | 源码可见的 `.py` 文件 | `random`, `csv`, `json`, `datetime` |
| C 扩展库 | 编译后的 `.pyd` / `.so` 文件 | `math`, `sys`, `time` 的部分函数 |

C 扩展用于性能敏感的底层运算,但对外暴露的调用接口与纯 Python 函数无异.这就是 Python 被称为"胶水语言"的原因:**接口是 Python,内核可以是 C**.

#### 5. 模块搜索路径:`sys.path`

`import` 按 `sys.path` 列表的顺序搜索模块:

```python
import sys
print(sys.path)
```

典型路径包括:

| 顺序 | 路径 | 说明 |
| :--- | :--- | :--- |
| 1 | 当前工作目录 | 运行脚本所在目录 |
| 2 | 标准库目录 | Python 安装目录下的 `Lib/` |
| 3 | 第三方库目录 | `site-packages/` |

`pip install numpy` 的本质,就是把 numpy 的源码或 wheel 包解压到 `site-packages/`,使 `sys.path` 能搜到它.

##### 5.1 手动添加自定义模块路径

如果自定义模块不在当前目录,可以手动追加路径:

```python
import sys
sys.path.append("my_modules")
from 质数判定模块 import ifp
```

#### 6. 命名冲突警告

如果当前目录有一个 `random.py`,那么 `import random` 会**优先导入这个本地文件**,而不是标准库的 `random`.这会导致大量诡异 bug.

| 禁止的命名 | 原因 |
| :--- | :--- |
| `random.py` | 与标准库冲突 |
| `math.py` | 与标准库冲突 |
| `json.py` | 与标准库冲突 |
| `csv.py` | 与标准库冲突 |

**规则**:自定义模块的文件名不要与任何标准库或常用第三方库重名.

##### 6.1 模块名本身的合法性

文件名必须是合法的 Python 标识符,才能被常规 `import` 导入:

| 文件名 | 能否 `import` | 原因 |
| :--- | :--- | :--- |
| `质数判定模块.py` | 可以(Python 3 支持中文) | 合法标识符 |
| `my_module.py` | 可以 | 合法标识符 |
| `VE2马尔科夫链[2×2].py` | 不可以 | 含 `[` `]` `×`,不是合法标识符 |
| `2test.py` | 不可以 | 数字开头 |

> 建议:文件名使用英文小写 + 下划线,避免中文、空格、特殊字符,以保证跨平台与工具链兼容.

#### 8. 与数学/计算理论的关联

##### 8.1 模块化即抽象分层

数学中,一个复杂定理通常被拆解为若干引理(lemma),每个引理独立证明,最后组合成完整证明.模块化编程与此同构:

| 数学 | 编程 |
| :--- | :--- |
| 引理 | 函数 / 模块 |
| 引理的证明 | 函数的实现 |
| 引用引理 | `import` |
| 定理的组合证明 | 主程序调用多个模块 |

##### 8.2 可组合性与命名空间

- **可组合性**:好的模块应当只暴露必要的接口,内部实现细节对外不可见.这对应数学中的"黑箱引理"——使用者只需知道引理成立,不需关心其证明细节.
- **命名空间**:`import mod` 而非 `import *`,相当于数学中给不同领域的符号加限定(如 $\mathbb{Z}$ 与 $\mathbb{R}$ 中的运算),避免符号冲突.

##### 8.3 与计算理论的关联

在 λ 演算中,程序由函数抽象和函数应用构成;模块系统可以看作对"名称绑定"的显式管理.Python 的模块机制虽然不是形式化系统,但它体现了同样的核心思想:**计算 = 命名 + 组合**.

#### 9. 快速参考

```python
# 导入整个模块
import mod
mod.func()

# 导入指定函数
from mod import func
func()

# 导入并起别名
import mod as m
m.func()

# 条件导入
try:
    import numpy
except ImportError:
    numpy = None

# 模块自运行守卫
if __name__ == '__main__':
    main()

# 查看模块文件位置
import mod
print(mod.__file__)

# 查看搜索路径
import sys
print(sys.path)
```

#### 10. 总结

| 层次 | 复用范围 | 机制 |
| :--- | :--- | :--- |
| 函数 | 同一文件内 | `def` 定义,直接调用 |
| 模块 | 跨文件 | `import` 导入 `.py` 文件 |
| 包 | 跨目录 | 含 `__init__.py` 的文件夹 |
| 第三方库 | 跨项目 | `pip install` 到 `site-packages/` |

函数是复用的第一层,模块是第二层.理解"库 = 一组放在可搜索路径中的函数与类",就理解了 Python 生态的基本构造方式.
